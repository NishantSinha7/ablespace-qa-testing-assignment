# Section 6 — Test Summary

Testing was performed on AbleSpace web staging at `https://staging.ablespace.io/` on 13–14 October 2026. The main functional checks were completed in desktop Google Chrome. Microsoft Edge and Mozilla Firefox were also smoke-checked, with no new issues reported in the same high-level areas. Responsive web checks used Chrome DevTools at 390 × 844, 768 × 1024, and 1024 × 1366 to approximate a mobile viewport, iPad Mini, and iPad Pro. These were emulations, not physical tablet tests.

The tested web workflows included onboarding, student creation with minimum required data, student search and refresh persistence, editing optional student details, goal creation, accuracy data capture, Undo, prompt tracking, Stats/Graph consistency, saving a student note, and the Worksheets empty state. Web workflows mostly behaved as expected. A note-count discrepancy was observed briefly: Notes count showed 2 after note entry and 1 after refresh while the saved note remained visible; recurrence was not established and it is recorded as OBS-01 rather than a confirmed bug.

The official Google Play Android app was also opened using the same login account. One mobile usability issue was observed: the “What's your role?” selector's options list was clipped at the right edge and overlapped by the on-screen keyboard; the role prompt remained during the recorded attempt, with a brief blank/loading state. This is reported as **BUG-01**, severity Medium and priority High, with a screenshot extracted from the recording. The issue should be retested after a fresh app launch on the iQOO Neo 9 Pro running Android 16, with the exact app version recorded. The student created on web staging was not visible in the public app; this is **not** classified as a bug because the web staging environment and public mobile app may use different backends/tenants (OBS-02).

Areas not tested include every Billing, Accommodations, Service Time, Family, Attachments, reports/export and worksheet-assignment workflow; exhaustive validation of all field boundaries; native iOS; physical iPad devices; and the full detailed regression suite in each alternate browser. Exact desktop browser and Android app versions were not recorded. Native device details recorded: iQOO Neo 9 Pro running Android 16. Security, penetration, injection, and load testing were intentionally excluded in accordance with the assignment rules.

If 1–2 more hours were available, the highest-value next steps would be to reproduce BUG-01 after a fresh Android app launch, record the exact app version, test long text and date-field validation with fictional values, and repeat the main student/goal workflows in one alternate desktop browser with its version recorded. The staging-versus-public-app data difference should only be pursued as a defect if product expectations confirm that those environments should share the same data source.
